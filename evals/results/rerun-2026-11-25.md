# Rerun, before and after (block 14, 2026-11-25)

Official scorecard: `scorecard-2026-11-25.md` (the "after" column below). Baseline: `scorecard-2026-11-17.md`.

## How it was run

- Same label-free bundles as the baseline (`python3 -m evals.inputs <set>`), 3 fresh Haiku runs per set and arm.
- **The real classifier subagent cannot run the fixed prompt.** It loads `.claude/agents/classifier.md` from the main checkout (master, unchanged since Oct 7). The fixes live on the study branch. A first set of 12 real-subagent runs today confirmed this: every transcript held master's rules. Those runs are kept as a third "before" measurement (`runs/2026-11-25-master-prompt/`).
- So before and after both ran through the file-read harness: the classifier subagent reads a rules file (master's prompt, or the branch's) and follows it in place of its own. Old and new go through the same path, so the comparison is fair. The known difference from production is that the rules arrive as a file, not as the system prompt.
- Injection: the block 13 production-framed run (`runs/2026-11-23-injection-prod/`), 1 repeat. No agent prompt on the injection path changed after it, so it was not repeated.

## New misses in the after arm

- n20 (1 of 3): "I'll send her the 3 competitor one-pagers" became EMAIL instead of I_OWE. The fix 1 rule widened EMAIL to follow-ups with a person, and this run read a promise to send as an email.
- Ledger run 2 (1 of 3): dropped two client WAITING_ON items (l17 pricing sheet, l23 intro). Fix 2's "only items owed to her personally" rule may be pruning real client items. That run had recall 0.9 (precision 1.0).

Both are single-run misses. They are worth a regression case each in round 2, and not worth reverting a fix that removed five steady failures.

## Caveats

- 3 runs per arm. A 1-note difference is within noise, but the five failures above went from steady to absent.
- The after numbers depend on the file-read harness. They become production numbers only once the branch is merged to master.
- Injection is 1 repeat, and the model lists tool calls rather than making them.
